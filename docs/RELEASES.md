# Полная сборка и накопительные обновления

Полные сборки Windows и macOS хранятся в релизе `v1.2.0`. Не заменять и не переименовывать эти файлы: установщики используют их адреса и SHA-256 для восстановления основы.

В начале README находятся прямые ссылки на полные сборки и текущий апдейт. Каждый новый релиз обновления также начинается с этих ссылок. Метка Latest принадлежит новому апдейту: проверка обновлений в приложении читает `/releases/latest`.

Новый пользователь устанавливает полную сборку и один последний апдейт. Пользователю установленной версии нужен только последний апдейт. Апдейты включают полный актуальный набор исходников приложения и Python-обработчиков, поэтому установка промежуточных версий не требуется.

## Выпуск апдейта

1. Обновить версию в корневом и `app` package.json/package-lock.json, `app/updates.cjs` и обоих `scripts/Upgrade-SoundSync.*`.
2. Обновить таблицу загрузок README и добавить `docs/releases/<версия>.md` со ссылками на полную сборку, изменениями и фактически выполненными проверками.
3. Собрать оба пакета: `node scripts/build-upgrades.mjs`. Если Python не доступен как `python3`, указать его путь в `SOUNDSYNC_PYTHON`.
4. Выполнить `python scripts/check-update-packages.py`, подходящие проверки изменённого поведения и сверить состав пакетов. Нативные проверки Windows/macOS описывать только после фактического выполнения.
5. Закоммитить и отправить исходники. Запустить `python scripts/publish-cumulative-release.py --commit <полный SHA коммита>`. Скрипт использует `GH_TOKEN`/`GITHUB_TOKEN` или Git Credential Manager, не выводит секреты. Пакеты публикуются из локальной папки dist.

Публикация сначала создаёт draft-релиз с тегом текущей версии и указанным коммитом. Затем загружает два ZIP и контрольные суммы, сверяет размеры и SHA-256 GitHub и только после этого публикует релиз как Latest. При ошибке остаётся draft, который можно безопасно дополнить повторным запуском. Опубликованные версии не перезаписываются.

Старый workflow `test-upgrade.yml` и `publish-update-release.py` предназначены для ремонта существующего релиза 1.2.3; для новых релизов их не использовать.

Полную сборку выпускаем заново при изменении основы, которую нельзя надёжно восстановить существующим установщиком. Тогда обновляем базовые URL и контрольные суммы в установщиках и таблице загрузок.
